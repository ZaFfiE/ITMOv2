Findings
- app/api.py: create_review accepts payload: dict and accesses payload["diff"] directly. Missing validation will raise KeyError → 500 if the field is absent or wrong type. Use a Pydantic model so FastAPI returns 422 on invalid input.
- app/review_service.py: review(diff: str) sends the entire diff to the LLM with no size guard. Large PRs can exceed context limits, causing failures, latency spikes, or high cost. Add max size, truncation, or chunking/summarization.
- app/api.py and app/review_service.py: No error handling around llm.generate. Network/LLM errors will surface as 500 with no useful message. Wrap and convert to HTTPException with an appropriate status (e.g., 502/503) and log details.
- app/review_service.py: Prompt is vulnerable to prompt injection via diff content. Attackers can include instructions in the diff to steer the LLM. Add strong delimiters and explicit instructions to ignore content instructions in the diff, or apply a system prompt.
- app/api.py: API contract is implicit. No response_model, and status for creation isn’t set. Clients won’t get a documented schema; consider status_code=201 and a response model for {"comment": str}.
- app/dependencies import: The global review_service instance will be shared across requests. If the underlying llm client isn’t thread-safe, concurrent requests may race. Ensure thread safety or create per-request instances.
- app/api.py: Synchronous endpoint may block a worker while waiting on the LLM. If the LLM call is I/O bound, consider async with an async client or run sync work in the threadpool explicitly if needed. FastAPI runs sync endpoints in a threadpool by default, but be mindful of pool exhaustion under load.
- Typing: dict[str, str] requires Python 3.9+. If you target 3.8, use Dict[str, str] from typing. This appears in both the service and API.
- Internationalization: Prompt is English while the surrounding context may expect Russian output. Align language expectations or make it configurable.
- Tests: No tests for the new endpoint or service. Add tests for happy path, missing/invalid payload, LLM error propagation, and large diff handling.
Open questions
- What Python version(s) are we targeting?
- Should the endpoint be authenticated or rate-limited?
- Expected response language and structure beyond a single comment string?
- Maximum acceptable diff size and desired behavior when exceeded (truncate, summarize, reject)?
- Is the LLM client thread-safe and does it support async?
