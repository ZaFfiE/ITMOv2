# Few-shot

- Артефакт Практики 1: practices/practice_01/prompts.md (Master Prompt v1) и practices/practice_01/problem.md.
- Что хотим улучшить: добиться структурированного ответа (summary/risks/checks) с обязательными ссылками file:line и воспроизводимыми checks для каждого риска; устранить общие ответы без evidence.

## Примеры

### Хороший результат

- Findings:
  - app/review_service.py:19 — новая функция review принимает diff-строку и формирует prompt без указания требований к ссылкам; риск «общие ответы LLM».
  - app/api.py:35 — добавлен POST /api/reviews, проксирующий diff; отсутствуют валидации входных данных.
- Risks:
  - R1: Недостаточная структурированность prompt может давать общие ответы.
    Check: Запустить llm.generate с diff без инструкций, проверить наличие file:line ссылок в ответе — ожидаемо <30% (baseline из problem.md).
- Metrics:
  - Доля утверждений с file:line: 2/2 = 100% — соответствует ≥90%.
  - Рисков > 3: 0 — соответствует.
  - Checks: R1 имеет воспроизводимый check — соответствует.
- Fixes to P1:
  - Обновить @practices/practice_01/problem.md: уточнить, что prompts должны требовать ссылки file:line и checks.

### Плохой результат

- «Код можно улучшить», «Добавьте валидаторы», без ссылок на строки, без конкретных проверок, общие слова вроде «повысить безопасность», выводы без привязки к diff.

## Запрос

Контекст:
- Ты помогаешь студенту/ревьюеру провести проверку учебного PR и валидировать файл с проблемой и метриками.
- Входные материалы: diff из @practices/practice_01/TRAINING_PR.diff и описание @practices/practice_01/problem.md.

Задачи:
1) Проведи ревью PR на основе diff. Для каждого замечания обязательно укажи file:line, например app/api.py:35, и дай краткий, воспроизводимый check (как перепроверить). Избегай домыслов вне diff.
2) Проверь @practices/practice_01/problem.md на корректность заполнения относительно задач ревью. Отметь, выполняются ли метрики: доля утверждений с file:line ≥ 90%, «Рисков > 3» — 0, наличие ≥1 check на риск. Если метрика не достигается — укажи, что надо изменить в ответе.
3) После получения результата внеси изменения в @practices/practice_02/prompts.md в строке «Few-shot», заполнив столбцы «Конкретное изменение», «Проверка» и «Что отклонили», с ссылкой на конкретный файл/раздел Практики 1, а также заполни @practices/practice_02/few_shот/experiment.md согласно контексту. Также скопируй данный промпт без изменений в practices/practice_02/few_shot/experiment.md, сохранив уникальность техники few-shot, примеры и т.д

Формат ответа:
- Findings: список фактов с ссылками file:line.
- Risks: список с краткой формулировкой и для каждого — воспроизводимый check.
- Metrics: оценка выполнения метрик из problem.md с расчётом долей/количеств.
- Fixes to P1: конкретные изменения в файлах Практики 1 (ссылки на разделы/строки).

## Что получили

Findings:
- app/review_service.py:19 — новая функция review принимает diff-строку и не задаёт структуру ответа.
  Check: unit-тест ReviewService.review("diff") с заглушкой llm.generate; убедиться, что возвращается только {"comment": "..."}.
- app/review_service.py:20 — prompt формируется без требований к ссылкам file:line и структуре summary/risks/checks.
  Check: передать короткий diff и проверить, что в ответе llm.generate отсутствуют обязательные секции.
- app/review_service.py:22 — ответ сервиса — только {"comment": answer}, нет summary/risks/checks.
  Check: проверить ключи результата метода review — ожидается только "comment".
- app/api.py:35-37 — добавлен POST /api/reviews, проксирующий diff без схемы и валидации.
  Check: POST /api/reviews с {} — ожидается 500 (KeyError), т.к. payload["diff"].

Risks:
- R1: Неструктурированный prompt → общие ответы без ссылок file:line.
  Evidence: app/review_service.py:20, app/review_service.py:22.
  Check: вызвать review на TRAINING_PR.diff; убедиться, что нет summary/risks/checks и ссылок file:line.
- R2: Нет валидации тела запроса → 500 при отсутствии "diff".
  Evidence: app/api.py:37 (payload["diff"]).
  Check: POST /api/reviews с {} — фактически 500, вместо ожидаемого 4xx при схеме.
- R3: Нет ограничения размера diff → риск деградации/стоимости.
  Evidence: app/api.py:35-37 (проксирование), app/review_service.py:20 (diff включается целиком в prompt).
  Check: отправить очень большой diff и зафиксировать, что он уходит в LLM без отсечки.

Metrics:
- Доля утверждений с file:line: 4/4 = 100% — соответствует ≥ 90%.
- Рисков > 3: 0 — соответствует (рисков 3).
- Наличие ≥1 check на риск: 3/3 — соответствует.
